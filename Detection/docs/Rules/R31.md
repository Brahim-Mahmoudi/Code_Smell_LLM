# Smell: Raw Vision Payload (RVP)

## Motivation

When using vision-enabled LLMs (like GPT-4 Vision, Claude with vision, or Gemini Pro Vision), it's critical to manage image inputs carefully. These models allow sending images such as UI screenshots, diagrams, or photos alongside text, but the size, resolution, and detail level of images directly affect:

- **Latency** and response time
- **Cost** per API call (images consume many tokens)
- **Context window** usage
- **Model focus** and accuracy
- **Privacy** and compliance risks

Not managing vision payloads explicitly can lead to:
```python
#  Raw, unprocessed vision payload
def describe_bug(screenshot_bytes):
    response = client.responses.create(
        model="gpt-4.1-mini",
        input=[{
            "role": "user",
            "content": [
                {"type": "input_text", "text": "Describe the bug"},
                {"type": "input_image", "image": screenshot_bytes}  # Full resolution
            ]
        }]
    )

#  Preprocessed vision payload with explicit controls
def describe_bug(screenshot_bytes):
    small_image = resize_and_crop(screenshot_bytes, max_side=1024)
    response = client.responses.create(
        model="gpt-4.1-mini",
        input=[{
            "role": "user",
            "content": [
                {"type": "input_text", "text": "Describe the bug"},
                {"type": "input_image", "image": small_image, "detail": "low"}
            ]
        }]
    )
```

Sending raw, unbounded vision payloads causes:
- **Cost spikes** from unnecessarily large token consumption
- **Latency issues** from processing high-resolution images
- **Rate limit exhaustion** when sending multiple large images
- **Model focus problems** when critical details are lost in large screenshots
- **Privacy leaks** from unfiltered interface elements
- **Context truncation** that's opaque to developers

## Detection Strategy (high-level view)

1. **AST parsing**  
   Parse the source code and build an abstract syntax tree with parent/context information.

2. **Identify vision API calls**  
   `isVisionModelCall(node)` detects:
   - OpenAI vision API calls (`chat.completions.create` with image content)
   - Anthropic Claude vision messages (`messages.create` with image type)
   - Google Gemini vision content (`generate_content` with image parts)
   - LangChain vision chains (HumanMessage with image_url)
   - Other multimodal API calls

3. **Verify image content presence**  
   `hasImageContent(node)` checks for:
   - `type: "image"` or `type: "image_url"` in content
   - Image data in message content array
   - Base64 encoded images
   - Image URLs or file paths
   - Vision-specific content structures

4. **Check for image preprocessing**  
   `hasImagePreprocessing(node)` verifies presence of:
   - Image resizing functions (resize, thumbnail, scale)
   - Cropping operations (crop, crop_to_region)
   - Dimension constraints (max_side, max_width, max_height)
   - File size validation or limits
   - Image optimization utilities (optimize, compress)
   - Custom preprocessing pipelines

5. **Check for explicit detail configuration**  
   `hasExplicitDetailLevel(node)` verifies presence of:
   - `detail` parameter with values ("low", "high", "auto")
   - Resolution settings
   - Quality parameters
   - Token budget controls
   - Provider-specific detail configurations

6. **Detection logic**  
   Reports Raw Vision Payload when ALL conditions are met:
   - Call is to a vision-capable model
   - AND contains image content
   - AND lacks image preprocessing
   - AND lacks explicit detail level configuration

7. **Smart exclusions**  
   Ignores calls that:
   - Already use preprocessed images (from helper functions)
   - Have explicitly constrained image sources
   - Are part of thumbnail or preview generation flows
   - Use images from validated pipelines
   - Have preprocessing in parent scope

8. **Reporting**  
   `REPORT: Unbounded vision payloads at line N`

def process_image_with_budget(image_path):
    """Process image within defined budgets."""
    image = Image.open(image_path)
    
    # Check file size
    file_size_mb = os.path.getsize(image_path) / (1024 * 1024)

    # Optimize
    buffered = BytesIO()
    image.save(buffered, format="JPEG", quality=quality, optimize=True)

### Helper Functions
```python
def resize_and_crop(image_bytes, max_side=1024, crop_region=None):
    """Resize and optionally crop image to budget."""
    image = Image.open(BytesIO(image_bytes))
    
    # Crop to relevant region if specified
    if crop_region:
        image = image.crop(crop_region)
    
    # Resize maintaining aspect ratio
    if max(image.size) > max_side:
        image.thumbnail((max_side, max_side), Image.Resampling.LANCZOS)
    
    # Return optimized bytes
    buffered = BytesIO()
    image.save(buffered, format="PNG", optimize=True)
    return buffered.getvalue()

def validate_image_budget(image_bytes, max_mb=5):
    """Validate image against size budget."""
    size_mb = len(image_bytes) / (1024 * 1024)
    if size_mb > max_mb:
        raise ValueError(f"Image exceeds budget: {size_mb:.2f}MB > {max_mb}MB")
    return True
```

## Limitations

- **Cannot detect** all image preprocessing in external libraries
- **May not recognize** custom image optimization utilities
- **Conservative on dynamic pipelines** where images are processed elsewhere
- **Cannot validate** if preprocessing is adequate for the use case
- **Misses** detail settings passed through configuration files
- **Cannot detect** when images are pre-optimized before reaching the code

---

## Recommended Practices

1. **Always preprocess images** before sending to vision APIs
2. **Set explicit detail levels** based on task requirements:
   - `low`: UI descriptions, general content, coarse inspection
   - `high`: Fine-grained analysis, technical diagrams, OCR
   - `auto`: Let provider decide (avoid for reproducibility)
3. **Define image budgets**:
   - Maximum resolution (e.g., 1024x1024 for low detail, 2048x2048 for high)
   - Maximum file size (e.g., 2-5MB per image)
   - Maximum number of images per request (e.g., 3-5)
4. **Crop to relevant regions** instead of sending full screenshots
5. **Extract text when possible** instead of sending screenshots of text
6. **Document image budgets** alongside other resource limits
7. **Monitor token usage** from vision inputs to optimize costs
8. **Implement preprocessing helpers** for consistent image handling
9. **Consider privacy** when sending screenshots (filter sensitive data)
10. **Test with realistic images** to validate budget effectiveness
