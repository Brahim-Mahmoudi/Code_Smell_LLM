# Smell: Anonymous Inference Call (AIC)

## Motivation

Many LLM providers expose optional request fields that allow applications to attach a stable end-user identifier or equivalent metadata to each inference call. This enables:

- **Traceability** across sessions and tenants
- **Abuse monitoring** and detection
- **Accountable auditing** for compliance
- **User-scoped analytics** in multi-user systems
- **Cost attribution** per user or tenant
- **Rate limiting** per user

Not attaching user identifiers can lead to:
```python
#  Anonymous inference call in multi-user context
def get_response(user_session_id, prompt):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.7
        # No user identifier attached
    )
    return response.choices[0].message.content

#  Traceable inference call with user attribution
def get_response(user_session_id, prompt):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.7,
        user=user_session_id  # Explicit user attribution
    )
    return response.choices[0].message.content
```

Anonymous inference calls in multi-user contexts cause:
- **Attribution failures** when investigating incidents or hallucinations
- **Cost spike mysteries** without user-level breakdown
- **Rate limit confusion** when limits are exhausted
- **Weak abuse detection** without user-level patterns
- **Debugging difficulties** when reproducing user-specific issues
- **Governance gaps** in safety and compliance workflows
- **Analytics blindspots** for user behavior understanding

---

## Detection Strategy (high-level view)

1. **AST parsing**  
   Parse the source code and build an abstract syntax tree with parent/context information.

2. **Identify text-generating calls**  
   `isTextGeneratingCall(node)` detects:
   - OpenAI chat completions
   - Anthropic message creation
   - Google Gemini content generation
   - LangChain LLM invocations
   - Other text generation API calls

3. **Check for multi-user context**  
   `hasMultiUserContext(node)` verifies presence of:
   - User session parameters in function signature
   - Authentication context variables
   - User ID or session ID in scope
   - Request context indicating multi-user environment
   - Web framework request objects (Flask, FastAPI, Django)

4. **Check for user attribution**  
   `hasUserAttribution(node)` verifies presence of:
   - `user` parameter in API call
   - `user_id` or equivalent identifier
   - `metadata` with user information
   - Provider-specific attribution fields

5. **Detection logic**  
   Reports Anonymous Inference Call when ALL conditions are met:
   - Call generates text from an LLM
   - AND operates in a multi-user context
   - AND lacks user attribution parameter

6. **Multi-user context detection**  
   Identifies multi-user contexts by checking:
   - Function parameters (user_id, session_id, user, account_id)
   - Parent scope variables
   - Web framework decorators (@login_required, @authenticated)
   - Request objects in scope
   - Authentication middleware presence

7. **Smart exclusions**  
   Ignores:
   - Single-user applications or scripts
   - System-level or administrative calls
   - Calls where user attribution is in parent wrapper
   - Development/testing contexts explicitly marked

8. **Reporting**  
   `REPORT: Anonymous Inference Call at line N`

###  Properly Attributed Inference Calls
```python
# OpenAI with user attribution
@app.route('/chat')
@login_required
def chat_endpoint():
    user_id = session.get('user_id')
    prompt = request.json['prompt']
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        user=user_id  # Explicit user attribution
    )
    return response.choices[0].message.content

# Pseudonymized user identifier
import hashlib

def get_pseudonymized_user_id(email):
    """Create stable pseudonymous identifier."""
    return hashlib.sha256(email.encode()).hexdigest()[:16]

def process_request(user_email, query):
    user_id = get_pseudonymized_user_id(user_email)
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": query}],
        user=user_id  # Pseudonymous but traceable
    )
    return response.choices[0].message.content

# Multi-tenant with tenant ID
def handle_tenant_request(tenant_id, user_id, prompt):
    # Composite identifier for multi-tenant systems
    attribution_id = f"{tenant_id}:{user_id}"
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        user=attribution_id
    )
    return response.choices[0].message.content

# Anthropic with metadata
async def handle_message(user_session_id, message):
    response = await anthropic_client.messages.create(
        model="claude-3-opus-20240229",
        max_tokens=1024,
        messages=[{"role": "user", "content": message}],
        metadata={
            "user_id": user_session_id  # User attribution in metadata
        }
    )
    return response.content[0].text

# LangChain with custom callbacks
class UserAttributionCallback(BaseCallbackHandler):
    def __init__(self, user_id):
        self.user_id = user_id
    
    def on_llm_start(self, serialized, prompts, **kwargs):
        # Log user attribution
        logger.info(f"LLM call for user: {self.user_id}")

def answer_question(user_id, question):
    llm = ChatOpenAI(
        model="gpt-4",
        model_kwargs={"user": user_id}  # User attribution
    )
    callback = UserAttributionCallback(user_id)
    chain = LLMChain(llm=llm, prompt=prompt_template)
    result = chain.run(question, callbacks=[callback])
    return result

# FastAPI with proper attribution
@app.post("/generate")
async def generate_text(
    request: GenerateRequest,
    current_user: User = Depends(get_current_user)
):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": request.prompt}],
        user=current_user.id  # User attribution from auth context
    )
    
    # Log for additional traceability
    logger.info(
        "LLM inference",
        extra={
            "user_id": current_user.id,
            "model": "gpt-4o",
            "request_id": response.id
        }
    )
    
    return {"result": response.choices[0].message.content}

# Centralized client wrapper with automatic attribution
class AttributedLLMClient:
    def __init__(self, base_client):
        self.client = base_client
    
    def create_completion(self, user_id, **kwargs):
        """Automatically attach user attribution."""
        return self.client.chat.completions.create(
            user=user_id,  # Always include user
            **kwargs
        )

# Usage
attributed_client = AttributedLLMClient(OpenAI())

def handle_request(user_id, prompt):
    return attributed_client.create_completion(
        user_id=user_id,
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

# Session-based attribution
from flask import session

def get_current_session_id():
    """Get or create session identifier."""
    if 'llm_session_id' not in session:
        session['llm_session_id'] = str(uuid.uuid4())
    return session['llm_session_id']

@app.route('/chat')
def chat():
    session_id = get_current_session_id()
    prompt = request.json['prompt']
    
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        user=session_id  # Session-level attribution
    )
    return response.choices[0].message.content
```

### Attribution Strategies by Context
```python
# Strategy 1: Authenticated users
def handle_authenticated_request(user):
    user_id = f"user:{user.id}"
    # ... LLM call with user=user_id

# Strategy 2: Anonymous sessions
def handle_anonymous_request(session):
    session_id = f"session:{session.id}"
    # ... LLM call with user=session_id

# Strategy 3: Multi-tenant
def handle_tenant_request(tenant, user):
    attribution = f"tenant:{tenant.id}:user:{user.id}"
    # ... LLM call with user=attribution

# Strategy 4: API keys
def handle_api_request(api_key_hash):
    attribution = f"apikey:{api_key_hash}"
    # ... LLM call with user=attribution

# Strategy 5: Service accounts
def handle_background_job(job_id, initiated_by):
    attribution = f"job:{job_id}:user:{initiated_by}"
    # ... LLM call with user=attribution
```

## Limitations

- **Cannot detect** user attribution passed through wrapper classes or middleware
- **May not recognize** custom attribution mechanisms outside standard parameters
- **Conservative on** detecting multi-user context in complex frameworks
- **Cannot validate** if the user identifier is appropriately pseudonymized
- **Misses** attribution when set in configuration files or environment
- **Cannot detect** when attribution is added by infrastructure (proxies, gateways)

---

## Recommended Practices

1. **Always attach user identifiers** in multi-user contexts
2. **Use pseudonymized identifiers** (hashed emails, internal IDs) rather than PII
3. **Maintain consistent attribution** across all LLM providers
4. **Document your attribution strategy** in code and architecture docs
5. **Log attribution alongside model calls** for debugging and auditing
6. **Create centralized client wrappers** that enforce attribution
7. **Include attribution in monitoring dashboards** for cost and usage tracking
8. **Test attribution propagation** in integration tests
9. **Audit anonymous calls** regularly to catch gaps
10. **Consider composite identifiers** for multi-tenant systems (tenant:user)

## Attribution Parameter by Provider

| Provider | Parameter | Format | Example |
|----------|-----------|--------|---------|
| OpenAI | `user` | String identifier | `user="user_123"` |
| Anthropic | `metadata.user_id` | Metadata dict | `metadata={"user_id": "user_123"}` |
| Google | `user_metadata` | Dict | `user_metadata={"id": "user_123"}` |
| Cohere | `user_id` | String | `user_id="user_123"` |
| Azure OpenAI | `user` | String | `user="user_123"` |

## Privacy Considerations
```python
#  Good: Pseudonymized identifier
user_id = hashlib.sha256(user_email.encode()).hexdigest()[:16]

#  Bad: Raw personal data
user_id = user_email  # Don't send PII to LLM providers

#  Good: Internal stable ID
user_id = f"user:{user.internal_id}"

#  Bad: Sensitive business data
user_id = f"{user.name}:{user.company}:{user.role}"
```
