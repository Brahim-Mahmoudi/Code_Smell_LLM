# Smell: Overspecified Sampling Parameters (OSP)

## Motivation

When using LLMs, developers have access to multiple sampling controls that shape the randomness of text generation, most commonly:
- **temperature**: Controls randomness by scaling logits
- **top_p** (nucleus sampling): Samples from smallest set of tokens with cumulative probability ≥ p
- **top_k**: Samples from top k most likely tokens

These parameters are **not independent** — they all restrict or reweight the next-token distribution. Their exact semantics and interactions vary across providers and model families.

Not managing sampling parameters carefully can lead to:
```python
#  Overspecified sampling parameters
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a story"}],
    temperature=0.9,
    top_p=0.95,      # Conflicts with temperature
    top_k=50         # Further complicates behavior
)

#  Single, explicit sampling control
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a story"}],
    temperature=0.9  # Clear, single control
)
```

Overspecifying sampling parameters causes:
- **Unpredictable decoding behavior** when multiple constraints interact
- **Poor reproducibility** across providers with different implementations
- **Difficult debugging** when output quality changes unexpectedly
- **Portability issues** when migrating between models or APIs
- **Silent quality regressions** from unclear parameter dominance
- **Maintenance complexity** when tuning generation behavior

---

## Detection Strategy (high-level view)

1. **AST parsing**  
   Parse the source code and build an abstract syntax tree with parent/context information.

2. **Identify LLM calls**  
   `isLLMCall(node)` detects API calls to language models.

3. **Check for parameter overspecification**  
   `hasOverspecifiedSampling(node)` detects when multiple sampling parameters are set simultaneously:
   - **Direct overspecification**: Call has both `temperature` AND (`top_p` OR `top_k`)
   - **Context overspecification**: Parent `with_options()` context sets conflicting parameters

4. **Detection logic for direct calls**  
   Flags calls where:
   - `temperature` is explicitly set
   - AND (`top_p` is set OR `top_k` is set)

5. **Detection logic for context managers**  
   Walks up the AST to check for `with_options()` contexts:
   - Identifies `with` statements containing the call
   - Checks if `with_options()` sets conflicting sampling parameters
   - Reports if both temperature and (top_p or top_k) are configured

6. **Smart exclusions**  
   Ignores:
   - Calls with only one sampling parameter set
   - Default parameter values (not explicitly set by user)
   - Provider-specific parameters that don't conflict

7. **Reporting**  
   `REPORT: Overspecified sampling at line N`

## Examples

###  Overspecified Sampling Parameters
```python
# Multiple conflicting sampling controls
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Generate content"}],
    temperature=0.9,
    top_p=0.95,      # Conflicts with temperature
    top_k=50         # Further overspecification
)

# OpenAI with multiple controls
response = openai.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "Write a story"}],
    temperature=0.8,
    top_p=0.9        # Conflicts with temperature
)

# LangChain with overspecification
llm = ChatAnthropic(
    model="claude-3-opus-20240229",
    temperature=1.0,
    top_p=0.95,      # Overspecified
    top_k=40
)

# Overspecification in context manager
with client.with_options(temperature=0.9, top_p=0.95):
    response = client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": "Generate"}]
    )

# Nested overspecification
def generate_text():
    with client.with_options(temperature=0.8):
        return client.messages.create(
            model="claude-3-5-sonnet-20241022",
            messages=[{"role": "user", "content": "Write"}],
            top_p=0.9    # Conflicts with context temperature
        )
```

###  Properly Specified Sampling Parameters
```python
# Single control: temperature only
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a creative story"}],
    temperature=0.9  # Clear, documented choice
)

# Single control: top_p only
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Generate diverse outputs"}],
    top_p=0.95       # No temperature set
)

# Single control: top_k only
response = openai.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "Brainstorm ideas"}],
    top_k=50         # Clear constraint
)

# Task-specific temperature settings
def generate_creative_content(prompt):
    """Creative generation with high temperature."""
    return client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.9  # Documented: creative tasks
    )

def generate_factual_content(prompt):
    """Factual generation with low temperature."""
    return client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.2  # Documented: factual accuracy
    )

def generate_deterministic(prompt):
    """Deterministic generation."""
    return client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.0  # Documented: deterministic
    )

# Centralized sampling configuration
SAMPLING_CONFIGS = {
    "creative": {"temperature": 0.9},
    "balanced": {"temperature": 0.7},
    "factual": {"temperature": 0.3},
    "deterministic": {"temperature": 0.0},
    "diverse": {"top_p": 0.95},      # Alternative: use top_p
    "focused": {"top_p": 0.5}
}

def generate_with_config(prompt, config_name="balanced"):
    """Generate with centralized sampling config."""
    config = SAMPLING_CONFIGS[config_name]
    return client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": prompt}],
        **config  # Single, explicit control
    )

# Context manager with single control
with client.with_options(temperature=0.8):
    response = client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": "Generate"}]
        # No additional sampling parameters
    )

# Documented sampling choice
def generate_story(topic):
    """
    Generate creative story.
    
    Sampling: temperature=0.9 for creative diversity.
    Rationale: Creative writing benefits from higher randomness.
    """
    return client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": f"Write a sci-fi story about {topic}"}],
        temperature=0.9
    )
```

### Sampling Parameter Guidelines by Task
```python
# Task-based sampling recommendations
TASK_SAMPLING = {
    # High creativity tasks
    "creative_writing": {"temperature": 0.9},
    "brainstorming": {"temperature": 0.8},
    "storytelling": {"temperature": 0.85},
    
    # Balanced tasks
    "general_chat": {"temperature": 0.7},
    "summarization": {"temperature": 0.5},
    "translation": {"temperature": 0.3},
    
    # Precision tasks
    "code_generation": {"temperature": 0.2},
    "data_extraction": {"temperature": 0.1},
    "classification": {"temperature": 0.0},
    
    # Deterministic tasks
    "structured_output": {"temperature": 0.0},
    "yes_no_questions": {"temperature": 0.0},
}

def generate_for_task(prompt, task_type):
    """Generate with task-appropriate sampling."""
    sampling = TASK_SAMPLING.get(task_type, {"temperature": 0.7})
    return client.messages.create(
        model="claude-3-5-sonnet-20241022",
        messages=[{"role": "user", "content": prompt}],
        **sampling
    )
```

## Limitations

- **Cannot detect** sampling overspecification in dynamically constructed configurations
- **May not recognize** provider-specific sampling parameter names
- **Conservative on** complex inheritance hierarchies or wrapper classes
- **Cannot validate** if the chosen sampling parameter is appropriate for the task
- **Misses** overspecification when parameters come from separate config files
- **Cannot detect** when conflicting parameters are set in different execution paths

---

## Recommended Practices

1. **Use a single primary sampling control** per LLM call
2. **Choose the right control for your use case**:
   - **temperature**: Most common, intuitive control (0.0 = deterministic, 1.0 = creative)
   - **top_p**: When you want nucleus sampling specifically
   - **top_k**: When you want a fixed number of candidate tokens
3. **Document your sampling choice** in code comments or configuration
4. **Match sampling to task requirements**:
   - 0.0-0.3: Factual, deterministic, structured outputs
   - 0.4-0.7: Balanced, general-purpose tasks
   - 0.8-1.0: Creative, diverse, exploratory generation
5. **Avoid extremes** (very high temperature can produce nonsense)
6. **Centralize sampling configurations** for consistency
7. **Test sampling changes** with regression suites
8. **Never combine** temperature with top_p or top_k
9. **Version control** sampling parameter choices
10. **Monitor output quality** when changing sampling parameters

## References

- Provider documentation often specifies which parameters can be combined
- Some providers ignore certain parameters when others are set
- Implementation details vary: OpenAI, Anthropic, Google, and others handle interactions differently
- Best practice: stick to one parameter per call for predictable, portable behavior
