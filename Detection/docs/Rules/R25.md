# Smell: LLM Temperature Not Explicitly Set (TNES)

## Motivation

When using language models through APIs, SDKs, or runtimes such as OpenAI, Anthropic, Hugging Face Transformers, LangChain wrappers, or Ollama, decoding hyperparameters govern output stochasticity. Temperature is a primary control knob for sampling randomness, alongside nucleus sampling (`top_p`) and top k sampling (`top_k`). If none of these are specified, the invocation relies on provider and model defaults, which may differ across providers and can change over time, reducing reproducibility and portability.

```python
# No explicit randomness control: relies on defaults (TNES)
response = openai.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Generate a story"}],
)

# Explicit randomness control via temperature
response = openai.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Generate a story"}],
    temperature=0.7,
)

# Explicit randomness control via top_p (temperature intentionally omitted)
response = openai.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Generate a story"}],
    top_p=0.9,
)
```

Not explicitly setting the temperature can lead to:

- Responses that are too deterministic or too random depending on default value
- Lack of control over output creativity/variability
- Inconsistent behavior across different LLM providers


---

## Detection strategy (high‑level view)

1. **AST parsing**  
   Parse the source and enrich nodes with parent pointers `(add_parent_info)`.

2. **Identify LLM calls**  
    `iisLLMCall(node)` detects different types of LLM calls:
    Direct API calls (OpenAI, Anthropic, etc.)
    LangChain constructors (ChatOpenAI, etc.)
    Text generation pipelines
    Gemini/Vertex AI calls

3. **Check temperature parameter**
    `hasNoTemperatureParameter(node)` verifies if temperature is absent:
    In direct named arguments
    Via kwargs (**params)
    In parameter dictionaries

4. **Reporting**  

   REPORT: LLM call without explicit temperature parameter at line`n `.

## Examples 

```python
# Unspecified randomness control (TNES)

chat = client.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Explain a concept"}]
)

# Fixed: explicit temperature for deterministic behavior
chat = client.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Explain a concept"}],
    temperature=0.0
)

# Fixed: randomness governed by top_p, temperature intentionally omitted
chat = client.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Explain a concept"}],
    top_p=0.9
)

# Fixed: randomness governed by top_k, temperature intentionally omitted
chat = client.chat.completions.create(
    model="gpt-4o-2024-11-20",
    messages=[{"role": "user", "content": "Explain a concept"}],
    top_k=50
)
```

## Limitations 

- Does not reliably detect randomness control parameters defined indirectly via variables with custom names unless they appear as temperature, top_p, or top_k at the call site or inside recognized parameter structures
- Does not verify temperature values (only presence/absence)
- Possible false positives on custom clients named similarly
- Does not track indirect calls (via wrapper functions)
